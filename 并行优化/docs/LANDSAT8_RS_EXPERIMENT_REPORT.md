# Landsat8 / RS 并行压缩实验整理

更新时间：2026-11-09。FMoW 暂不纳入主实验，因为其训练子集与归一化协议仍需重新核对。

## 1. 必须区分的三种模型与一个运行时对照

| 身份 | 通道分组 | 组间关系 | 理论阶段深度 | 当前状态 |
|---|---|---|---:|---|
| A 原始串行基线 | `[16,16,32,64,192]` | 5 组逐组串行，每组 Anchor→Non-anchor | 10 | 已有 checkpoint 与真实码流 |
| B 七组全串行消融 | `[16,16,32,64,64,64,64]` | 7 组逐组依赖，每组 Anchor→Non-anchor | 14 | **尚未实现/训练** |
| C 混合结构 | `[16,16,32,64,64,64,64]` | 前 3 组串行；后 4 组共享 PrefixContext | 8 | Landsat8、RS 均已训练 400 epoch |
| C-runtime-1 | 与 C 完全相同 | 同一结构，只将熵 coder worker 设为 1 | 8 | 运行时对照，不是模型 B |

因此，“hybrid-serial-runtime”不能写成“仅改变分组但仍串行”的结构消融。它只用于隔离 Python 多线程调度的影响。真正的模型 B 仍需新增模型文件并重新训练。

## 2. 已完成训练结果

- Landsat8：7 个 λ，`1024–65536`，全部完成 400 epoch；最佳点覆盖 BPP `0.0699–1.1303`。
- RS：6 个 λ，`32768–524288`，全部完成 400 epoch；最佳点覆盖 BPP `0.2009–1.0727`。
- 两者归一化均为 `65535`，与各自既有基线协议一致。
- 完整数值见 `experiments/landsat8_rs_summary/hybrid_training_best.csv`。

## 3. 真实码流试验（当前为 30 图中码率先导实验）

计时范围为完整 `compress()` / `decompress()`，计时边界执行 CUDA synchronize；BPP 来自实际熵码流字节数，不使用 likelihood 估算。Landsat8 使用 λ=16384，RS 使用 λ=262144。

| 数据集 | 模型/运行方式 | BPP | PSNR | MS-SSIM(dB) | 压缩(s) | 解压(s) |
|---|---|---:|---:|---:|---:|---:|
| Landsat8 | 原始 5 组串行 | 0.500830 | 46.3412 | 24.1210 | 0.24246 | 0.15518 |
| Landsat8 | 混合结构，1 worker | 0.554883 | 45.7508 | 23.6815 | 0.11307 | 0.12080 |
| Landsat8 | 混合结构，4 workers | 0.554883 | 45.7508 | 23.6815 | 0.20384 | 0.26822 |
| RS | 原始 5 组串行 | 0.773600 | 55.8583 | 32.2034 | 0.21481 | 0.13869 |
| RS | 混合结构，1 worker | 0.803630 | 55.5559 | 31.9823 | 0.11387 | 0.12175 |
| RS | 混合结构，4 workers | 0.803630 | 55.5559 | 31.9823 | 0.20351 | 0.27037 |

注意：A 与 C 在相同 λ 下的实际 BPP/画质不同，不能把其时间比直接解释为纯并行加速比。严格的并行实现对照是 C-runtime-1 与 C 的 4 workers，因为两者 checkpoint、图像、码流和重建完全相同。

## 4. 当前关键结论

- 四 worker 与单 worker 的 BPP、PSNR、MS-SSIM 完全相同，编码端/解码端 `y_hat` 逐元素严格一致，说明独立尾部码流的正确性已验证。
- Landsat8 的 4-worker 实现相对 1-worker：压缩耗时增加 `80.28%`，解压耗时增加 `122.03%`。
- RS 的 4-worker 实现相对 1-worker：压缩耗时增加 `78.72%`，解压耗时增加 `122.08%`。
- 当前不能把“真实加速”写成贡献。理论依赖深度由 10 降到 8 是结构性质，但 Python ThreadPool、GIL、线程建立/调度以及多个很短 rANS 任务的开销超过了并行收益。
- 混合结构单 worker 比原始基线更快是一个积极信号，但由于 RD 点并不严格匹配，只能作为先导结果，不能直接形成正式加速比结论。

## 5. 下一轮应补实验（按优先级）

1. 实现并训练模型 B（七组全串行），至少先在 Landsat8/RS 各选低、中、高 3 个 λ；这是证明“收益来自依赖拆除，而不只是重新分组”的核心消融。
2. 对 A/B/C 在相近 BPP 或相近 PSNR 处进行插值比较，正式报告 BD-Rate 与真实压缩/解压时间。
3. 将 C 的 4 个尾部 rANS 任务改为持久化进程池、C++/pybind 批量接口或真正支持批量多流的 entropy coder；不要继续依赖逐图创建/调度 Python 线程。
4. 在优化后的实现上跑完整验证集，并报告均值、中位数、P05/P95、GPU/CPU/软件版本、warm-up 数和 batch size=1。
5. 单独做概率参数预测与熵 coder 耗时拆分；拆分测试是诊断项，主表仍使用未插桩的完整流程时间。

## 7. 与其他方法的完整测试集对比

为避免训练验证集不一致，hybrid 的全部 checkpoint 已重新在 `/data/huzhenghao/ml/test/testdata` 上评估：Landsat8 每点 1700 张，RS 每点 1217 张。这里的 BPP 与其他方法一致，均为 likelihood 估计；真实码流和时间仍单独使用第 3 节的协议。

以各个对比方法为 reference、hybrid 为 tested，BD-Rate 为负表示 hybrid 节省码率：

| 数据集 | Reference | PSNR BD-Rate | MS-SSIM BD-Rate |
|---|---|---:|---:|
| Landsat8 | ELIC | -13.81% | -10.39% |
| Landsat8 | FTIC | +3.23% | +10.00% |
| Landsat8 | HL | +8.06% | +23.29% |
| Landsat8 | HPCM | +5.74% | +5.38% |
| Landsat8 | MLIC | +8.11% | +7.23% |
| Landsat8 | 原始 Mamba | +24.41% | +20.84% |
| Landsat8 | RWK | +3.22% | +7.21% |
| RS | ELIC | -17.93% | -13.45% |
| RS | FTIC | -15.56% | -5.76% |
| RS | HL | -41.64% | -31.93% |
| RS | HPCM | -8.59% | -2.86% |
| RS | MLIC | -22.36% | -14.98% |
| RS | 原始 Mamba | +13.56% | +12.39% |
| RS | RWK | -5.06% | -3.50% |

结论是：hybrid 在 RS 上仍优于多数外部方法，但相对原始 Mamba 有约 13% 的码率损失；在 Landsat8 上相对原始 Mamba 的损失更明显，约 21–24%。因此后续优化应首先恢复 Landsat8 的熵模型性能，而不能只围绕理论阶段数写贡献。
